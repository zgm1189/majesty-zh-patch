# 去掉实名认证（免认证版）

## 为什么要去

这个包的 `AndroidManifest.xml` 里 application 的 name 不是游戏自己的类，而是：

```xml
<application android:name="com.authentication.MyApp" ...>
```

`com.authentication.MyApp` 继承 `MultiDexApplication`，`onCreate` 干了两件事：

```java
b.a.a.c()                                      // 拿单例，构造器里 postDelayed(3000, runnable)
registerActivityLifecycleCallbacks(b.a.a)      // 注册 Activity 生命周期回调
```

3 秒后那个 runnable 执行 `b.a.h.b.e()`，发一个 HTTP 请求：

```
GET https://app2.byfen.com/get_country
```

回调里读 JSON 的 `cn` 字段，然后：

| 返回 | 行为 |
|---|---|
| `cn == true` | `b.a.h.b.a(activity)` → 弹「需完成实名认证后才能开始网络游戏」 |
| `cn == false` | 什么都不做 |
| **请求失败 / 超时** | `b.a.h.b.a(activity)` → **同样弹实名** |

第三行是关键：**接口不通就必弹**。外国玩家访问国内接口，超时是常态，所以基本都会卡在这一步。
而弹窗要填中国大陆身份证号，没有就过不去。

这套 SDK 是「百分网（byfen）」的渠道包带的，还配套一个 `BfArchiveActivity`（存档槽选择）
和 `BfFileProvider`，域名 `sdk.byfen.com`。

## 怎么去

### 切断点选在 `MyApp.onCreate`

全 dex 搜过，`b.a.a` 这个单例**只服务认证流程**：除了 `MyApp.onCreate` 注册它，
其余引用全部落在 `get_country` 的回调里。所以把注册去掉，整条链路就断了，
游戏本体一行代码都不用动。

`onCreate` 原本 21 个 code unit：

```
invoke-super {v2}, MultiDexApplication.onCreate            (3)
invoke-static {}, b.a.a.c()                                (3)
move-result-object v0                                      (1)
invoke-virtual {v2,v0}, registerActivityLifecycleCallbacks (3)
invoke-static {}, b.a.a.c()                                (3)
move-result-object v0                                      (1)
const v1, 0x1f01                                           (3)
invoke-virtual {v0,v1}, b.a.a.f(I)                         (3)
return-void                                                (1)
```

改成 `invoke-super` + `return-void` + 17 个 `nop`。**unit 数不变**，
所以 `insns_size`、try/catch 表、debug info 全部不用改，只换字节。

改完按 dex 规范重算 header：

```python
buf[0x0C:0x20] = sha1(buf[0x20:])        # signature
struct.pack_into("<I", buf, 0x08, adler32(buf[0x0C:]) & 0xFFFFFFFF)   # checksum
```

脚本：`tools/patch_dex_noauth.py`（按特征字节搜索，命中数不为 1 就报错退出，不硬编码偏移）。

```bash
python tools/patch_dex_noauth.py extracted/classes3.dex build/noauth/classes3.dex
```

### 打包

```bash
python tools/pack_apk.py --template build/majesty_zh.apk \
    --so build/so/libzhfont_lite.so \
    --replace classes3.dex=build/noauth/classes3.dex \
    --out build/out/unsigned_lite_noauth.apk
```

`--replace` 可以重复给，用来替换任意 apk 内条目。

## 怎么验证

dex 改得对不对，看两件事：

**1. 字节码**

```bash
dexdump -d build/noauth/classes3.dex | grep -A8 "MyApp.onCreate"
```

应该只剩 `invoke-super` + `return-void` + 一串 `nop // spacer`。

**2. 请求有没有发出去（对照实验）**

```bash
adb logcat -c && adb shell monkey -p com.herocraft.game.majesty.cn ... 1
sleep 15 && adb logcat -d | grep -i "app2.byfen"
```

| | `app2.byfen.com` 请求 |
|---|---|
| 未打补丁 | 有，启动后第 3 秒（`10:19:02` 启动 → `10:19:05` 请求） |
| 打了补丁 | **完全没有** |

实测补丁版启动后直接进存档，没有实名弹窗、没有隐私弹窗、没有崩溃。

## 一个容易搞错的点

启动加载界面底部那行「档案功能可以让多名玩家用同一部手机游戏而互不干扰」
**不是** byfen 的弹窗，是**游戏自己的教学提示**：

- 它的 key 是 `sLH35`，存在 `assets/translate.dat` 里
- 同组的 `sLH27`~`sLH37` 全是加载时的玩法提示（「用攻击旗促使英雄去攻击怪物」等）
- 在 `analysis/zh_entities.py` 里就能看到这条翻译

所以它跟着加载进度条出现、跟着加载结束消失，属于正常表现，不需要处理。

## 副作用

- byfen 的「档案」云存档入口不再被调用（本来也没进过游戏流程，`BfArchiveActivity` 没有任何外部 `startActivity` 引用）
- 游戏存档位置不变，仍在 `/sdcard/Android/data/com.herocraft.game.majesty_ne/files/`
- `sdk.byfen.com` 的请求还在（那是存档 SDK 自己的初始化），但不影响游玩，也不弹任何东西
- 覆盖安装同签名版本，存档保留；装回带认证的版本同样可以直接覆盖
